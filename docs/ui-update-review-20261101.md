## 已处理的问题

- **P1 · 手机排行溢出**：`frontend/src/styles/features/proxy-traffic.css` 的固定 320px 最小列宽超过窄屏卡片内宽，改为受容器宽度约束的最小值；30 台设备 + 历史未分类桶在 320px 仍可查看。
- **P1 · 连接失败却像可操作**：`ui-update-panel.ts` 的整套升级禁用时移除蓝色主操作样式；每项提供安装服务、核对入口、更新能力或选择文件的解释。
- **P1 · 更新服务后无法识别上传能力**：旧刷新逻辑只读任务状态，改为重新发现能力；服务升级后不必刷新整个网页即可启用 ZIP 选择。能力不再沿用上一次服务返回的旧值。
- **P1 · 限流后的重复请求**：网页读取等待响应头，跨页面刷新保留等待时间；强制手动检查也不能绕过。服务器已知正式标签时，API 限流会降级到同一仓库的正式附件地址，保留校验。
- **P2 · 无更新仍展示无效 UI 按钮**：即使服务未连接，也能按已读取的版本判断 UI 无更新并隐藏该行。`2026.11.01.6` 和 `2026.11.1.6` 等价。
- **P2 · 统计口径不够明确**：导出按钮明确为“导出当月每日用量 CSV”；历史未分类说明包含升级前存量、过期清理和其他明细缺失，不把所有差额都断言为某一次升级造成。分时柱明确为上下行合计。
- **P2 · 零峰值被写成 1 B**：图形的非零除数与真实峰值分开，真实零用量保持 0 B。
- **P2 · 点击区域与字形**：日历翻页及刷新/导出按钮至少 44px 高；两套 Noto SC 子集补齐缺少的 8 个汉字。

## 限流解决方案边界

匿名 REST 请求按出口 IP 共享每小时 60 次额度。遵守 `Retry-After` 与 `X-RateLimit-Reset`，避免限流后不断重试。[GitHub 官方说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)

本次降级改善已知标签的安装，不能代替首次发现最新版本。首次查询且没有缓存仍需等待或人工确认标签。官方下载也被限制时使用离线包；不默认引入未知代理，不向浏览器分发维护者令牌。

后续可由发布流程在成功上传全部附件后生成独立静态发行清单，并通过受维护的静态站点/CDN 分发，减少每台浏览器直接查询 REST API。清单应写入已发布标签及附件摘要，不能直接把主分支 `VERSION.json` 当作已发布版本。该发布基础设施方案未在本轮引入。
