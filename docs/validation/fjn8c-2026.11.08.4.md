# FJN8C / UI 2026.11.08.4 发布验证

日期：2026-11-08。范围：GitHub 附件下载入口选择、只读请求回退及等待备份的 UI 状态。

## 故障定位与真实网络验证

- 在原故障设备上，直连 `github.com` 首页及 Release 下载路径均在 15 秒探测超时内失败，未取得 HTTP 重定向。
- 经现有代理访问普通 GitHub 页面可完成探测，Release 下载路径却约 12 秒后返回 504，未返回附件重定向。
  这不能据此认定所有代理节点失效，也没有证书校验错误的证据。
- 同一校验附件经 `api.github.com/repos/yyhoworks/LocalDNS/releases/assets/<id>`，
  带 `Accept: application/octet-stream` 返回 HTTPS 302，再从 `release-assets.githubusercontent.com` 取得 HTTP 200。
  323 字节校验文件的摘要与发布的 API `digest` 一致。
- 修正后的安装器 1.4.2 在该设备直接联网运行：校验文件约 1.7 秒，37,632,889 字节的上版完整包约 28.8 秒。
  SHA-256 为 `63f4dbea1bc06991afd2df8c019745043fbff779d29dc09706e5dd9b55fec65c`，与发行摘要一致，ZIP CRC 通过。
- 网络探测没有使用离线包、关闭证书校验、修改系统代理或变更代理组选项；临时下载目录和文件已清理。

网络不可达的内部原因不能仅凭 504 判定为某个运营商或节点故障。本次确认并修复的是：
安装器只依赖失败的网页下载路径，没有使用已验证可达的同一附件官方 API 入口。

## 安全与兼容边界

附件 ID 必须为正整数，API 地址固定在本仓库 `releases/assets/`，原网页下载地址仍需精确匹配仓库、标签及文件名。
API 下载和后备下载共用临时文件、API 摘要检查和最终原子替换；完整包仍需通过 `SHA256SUMS.txt` 和全文件清单。
仅网络瞬时错误及限流触发备用地址；证书、HTTP 权限 / 缺失错误和错误摘要不重试。
失败不会覆盖已验证文件，部分下载字节清理后才使用备用入口。
没有附件 ID 的旧元数据及既有 API 限流降级继续保留官方下载路径。
