## 真实 Linux 隔离验证

以 nobody 身份启动临时副本，使用 loopback 高位端口和本地 DNS 应答夹具；服务控制适配器仅操作这些临时进程。

- FJN01 拒绝 `provider`，FJN8C 的国内 / 国外 / 国外 ECS 上游缺失该字段时无法启动；代理组拒绝该字段。
- FJN8C 对缺失 `prefetch` 的旧设置返回默认 `true`，但启动时不重写设置文件。因此在暂存目录显式补齐字段，保留严格文件/API 一致性校验。
- 部分 PUT 只改变 `prefetch`，其他开关保持不变。UI 原有空拨号地址、空 SOCKS5 载荷可用。
- 新旧内核均通过 UDP / TCP DNS 与相关 API 检查。
- 真实运行升级器上传路径：FJN01 → 上传 FJN8C → 完整备份确认 → 暂存迁移 → 隔离预检 → 目录切换 → 回滚 FJN01。
- 回滚后原始配置指纹和 UI 字节恢复，预检及升级后 DNS/API 通过。

临时目录和进程已清理；已有安装的二进制、配置和手工规则哈希未改变。未调用主机服务管理器启动或重启真实 DNS。
收尾时观察到原安装服务已停止，但未记录其测试前运行基线，不能据此判断停机原因或宣称现网健康验证通过。
初次临时夹具复制过多规则导致临时分区空间不足，清理本次目录后改用最小夹具完成验证。
其他架构未执行实机 DNS 验证。
