## 升级链路

`http://192.168.8.2:9100/upgrade` 返回 `localdns-updater/v2`，支持 `core/full/ui`，`coreUpload.format=upstream-zip`、最大 256 MiB、目标架构 amd64-v3。服务器实际运行的 `core_upload.py`、`upgrade_localdns.py`、`online_updater.py` 与当前工作区 SHA-256 完全一致。

现有上传流程会复制当前运行目录作为暂存，替换 `bin/localdns`，生成 `core-version.json`；不会导入 ZIP 附带的 UI 或默认配置。兼容性契约支持 FJN01，不要求只因新版本名而改硬编码列表。

推荐执行顺序：

1. 在版本弹窗的「内核」行选择原 ZIP，上传并准备。此阶段生产继续运行。
2. 下载完整备份到电脑，再选择备份文件校验 SHA-256。
3. 运行自带独立端口预检；验证核心版本、上游、客户端别名、功能开关、缓存预算、日志/任务接口及 DNS。
4. 校验后才切换内核并短暂重启 DNS；保留 UI 2026.11.05.4，使用真实内核状态和 `core-version.json` 标识 FJN01。
5. 复查 DNS UDP/TCP、主流客户端分流、缓存、上游、手动规则、别名及 UI；异常时使用升级流程的完整快照回退。

当前空闲磁盘约 288 MiB，应以正式上传前的空间预检为准；上传包、完整备份、暂存目录都需要空间。已经停止并清理本轮的临时试跑目录，报告保留在本机。

实际重启影响：当前 `querylog.persist=false`，内存中的查询日志不会跨重启保留；进程运行时长、累计请求等进程级统计会重新开始。配置、已落盘缓存/学习数据与 UI 浏览器偏好是另一类状态，应继续保留，不能以「保留设置」承诺内存日志不变。

## UI 适配建议

1. **修正八项开关的说明，保留现有分组布局。** 包内 UI 的文案明确说明请求屏蔽覆盖拦截名单、PCDN 和无结果；类型屏蔽开启处理 HTTPS/SVCB/SOA/PTR，关闭时仍对 FakeIP 域名处理 HTTPS/SVCB；客户端策略应解释名单内/外的直连与代理行为，避免只说「科学/不科学」。这些是包内资料所述的语义，未对全部 DNS 路由组合做行为测试。
2. **将缓存详情从原始文本改成表格。** 解析现有 `entries/capacity/bytes/budget/stale_ttl_seconds` 汇总和逐行域名、类型、`fresh/retained`，提供搜索，保留原文查看入口。不改缓存 API；FJMOS 已有这些字段，可同时兼容。
3. **在缓存参数弹窗补总内存预算。** 已验证 `POST /api/v1/cache/settings` 支持 `cache_memory_mb`。当前 UI 只展示预算分配、编辑条目上限/过期时间/写盘间隔；总预算输入可补充进现有弹窗，并清楚区分立即生效与待重启项。
4. **版本与打包。** 核心单独升级使用 `core-version.json`，不能提前修改本机发布元数据冒充已升级。后续正式打包时再将 `VERSION.json` 的 backend/releaseTag 切到 FJN01，记录原包和各架构 SHA-256；现有打包器已支持这四种架构。此次仍不发布 GitHub。

本轮未实施上述 UI 增强，未执行生产内核切换。证据位于本机忽略目录 `deployment/fjn01-review-20261105/`：`probe-report.json`、`ui-replay.json`、升级服务能力响应、包内文档提取和页面截图。
